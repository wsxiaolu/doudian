## 修复：安装/运行后程序打不开（真正根因 = 缺 sqlite3.dll）
- 用户反馈「安装后打不开」。此前已解决 VC++ 运行库捆绑（installer.iss 加 vcredist_x64.exe + [Code] VCInstalled 检测），并修过 [Code] 段 `;` 注释语法错误（已改 `//` + if 写法）。但装好带 VC++ 的 setup 后仍打不开 → 说明 VC++ 是叠加问题，真凶在别处。
- 排查：查 `build\windows\x64\runner\Release\` 发现 **没有 sqlite3.dll**。pubspec 依赖 `sqflite: ^2.3.0` + `sqflite_common_ffi: ^2.3.0`；在 Windows 上 sqflite 走 ffi，运行时需 `sqlite3.dll`，而纯 Dart 包里的原生 dll **不会被 flutter build 自动复制**进输出目录 → 程序启动加载 sqflite 失败、静默退出（散文件与安装版都打不开）。
- 代码检查 `lib\`：写文件均用 `getApplicationDocumentsDirectory()` / `getDatabasesPath()`（用户可写目录），排除 Program Files 写权限问题。
- 修复：
  1. 从 pub cache 复制：`sqflite_common_ffi-2.3.4+4/lib/src/windows/sqlite3.dll` → `build\windows\x64\runner\Release\sqlite3.dll`（2.88MB）。
  2. `installer.iss` 的 `[Files]` 用 `Source: "build\windows\x64\runner\Release\*"` 通配，已自动包含新 dll，无需改脚本。
  3. 根治：`scripts\build_windows.bat` 在 `flutter build windows --release` 后新增一步——用 powershell 从 `$env:LOCALAPPDATA\Pub\Cache` 递归找 `sqlite3.dll` 复制到 Release（避免下次 `flutter build` 重建目录时丢失）。注意该 powershell 行写在独立非括号块、内部用单引号避免 bat 解析 `()` 误闭合。
- 用户侧验证/收尾：① 双击 Release 目录 `doudian_shop.exe` 应可开；② 重跑 `scripts\build_installer.bat` 生成含 sqlite3.dll 的新 `installer\doudian_shop_setup.exe`；③ 卸载旧安装（控制面板→抖店订单管理器）后用新 setup 重装（或覆盖安装）。
- 结论：本工作区 Bash 出网被沙箱拦（curl 超时），但 pub cache 在本地，复制 sqlite3.dll 无需联网，可行。

## 修正：真正的「打不开」元凶 = AppDatabase.initPlatformFactory() 从未被调用
- 上面「缺 sqlite3.dll」只是叠加的次要问题。进一步追查本地模式仍打不开：在 `lib/main.dart` 的启动链（SupabaseService.initialize → themeProvider.load → authProvider.bootstrap → DataProvider）里，**从未调用 `AppDatabase.initPlatformFactory()`**。
- 该函数负责在 Windows/Linux 上调用 `sqfliteFfiInit()` 并把 `databaseFactory` 切到 `databaseFactoryFfi`；不调用的话 `openDatabase` 用默认工厂（桌面不支持），本地模式 `bootstrap()→_enterLocalMode→_profileDao.findById` 一开库就抛异常，在 `runApp` 之前未捕获 → **release 版静默退出**（这才是「打不开」主因）。
- 修复 `lib/main.dart`：
  1. import `dart:async` / `dart:io` / `data/local/app_database.dart`；
  2. `WidgetsFlutterBinding.ensureInitialized()` 之后立刻 `AppDatabase.initPlatformFactory()`；
  3. 启动链包进 `runZonedGuarded`，并在 `FlutterError.onError` 写 `C:\doudian\crash_log.txt`；初始化抛异常时 `runApp(_fatalScreen(...))` 显示可读错误，杜绝再次静默闪退。
- `dart analyze lib/main.dart` 已 0 error。需用户**重新跑 `scripts\build_windows.bat`**（会重建 Release 并自动补 sqlite3.dll）后再双击 `build\windows\x64\runner\Release\doudian_shop.exe` 验证。
- 教训：Flutter 桌面用 sqflite 必须在 runApp 前调 `sqfliteFfiInit()`+切换 factory；任何「release 静默退出」优先查 runApp 前的初始化链与顶层错误兜底。

## 修复：LNK1104 无法打开文件 doudian_shop.exe（链接期文件被占用）
- 用户重跑 `build_windows.bat` 时 `flutter build windows --release` 在链接阶段报 `LINK : fatal error LNK1104: 无法打开文件 "...\Release\doudian_shop.exe"`。这是 Windows 链接器的典型「目标 exe 被占用」错误，与代码无关。
- 根因：Release 目录里那个 `doudian_shop.exe`（8/2 旧构建，91KB）被某进程独占锁着（上一次运行/崩溃残留进程，或 Windows 错误报告 `WerFault.exe` 持有，少数情况是防病毒实时扫描锁文件），链接器无法覆盖。
- 修复 `scripts\build_windows.bat`：在 `flutter build windows --release` 之前加保险步——`taskkill /F /IM doudian_shop.exe` + `taskkill /F /IM WerFault.exe`（均 `>nul 2>nul` 静默，进程不存在不报错），随后 `if exist build\windows rmdir /s /q build\windows` 强制清掉旧 Windows 构建目录，确保无锁定文件残留。
- 用户侧即时操作：直接**重跑 `scripts\build_windows.bat`** 即可（脚本现已自动杀进程+清旧构建+重建，约 250s）。若仍报 LNK1104，多为 Windows Defender 实时防护锁 `build` 目录 → 把 `C:\doudian` 加进 Defender 排除项再重跑。
- 注意：rmdir build/windows 会让 Windows 构建完全重建（略慢但稳）；sqlite3.dll 自动复制步在 build 之后，顺序不受影响。

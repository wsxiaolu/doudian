## 修补：build_windows.bat 第二次闪退（「还是闪」）
- 上一版（带 `where flutter` guard）仍闪。根因有二：
  1. 括号陷阱：guard 块内 `echo ... 1)` / `echo ... 2)` 的圆括号提前闭合 `if (...)` 块，触发**语法错误、脚本在 `pause` 前中止** → 闪退。已重写为纯 `goto` 标签结构（`:noflutter`/`:haveflutter`/`:fail`/`:done`），echo 文本不含 `)`，彻底消除误解析。
  2. 行尾为 LF（非 Windows 标准 CRLF）。已确认部分 Windows 在 LF 下解析 `goto`/标签会异常，属潜在闪退诱因。
- 最终内容（已落盘）：`goto` 标签结构 + **自动探测 flutter 常见安装目录**（`C:\src\flutter`、`C:\flutter`、`%LOCALAPPDATA%\flutter`、`%USERPROFILE%\flutter`，命中即把 bin 加进 PATH），双击也能真正跑起来；`where flutter` 仍缺失才报清晰错误并 `pause`。
- **重要环境坑**：`build_windows.bat` 被本会话（WorkBuddy 文件监听）独占锁定。在我方环境内，Python 原地写、`mv` 重命名、PowerShell `Move/Copy` 全部 Permission denied；`cmd /c` 被安全策略拦截；只有 Write 工具能改写该文件，但 Write 只落 LF、无法产出 CRLF。故无法在我方把该文件转为 CRLF，只能交用户在自己的机器上转（见下方给用户的命令）。
- 结论：磁盘上的 `build_windows.bat` 逻辑已正确（自动探测+goto+不静默退出），仅行尾 LF。现代 Windows 10/11 下 LF .bat 一般可跑；若双击仍闪，用用户侧一行 PowerShell 转 CRLF，或直接在该 flutter 终端里运行脚本（最稳，同时解决 PATH 与行尾）。

## 修复：装后程序「打不开」（缺 VC++ 运行库）
- 用户反馈安装向导正常、但双击桌面图标打不开（静默退出）。根因：Flutter Windows release 默认不捆绑 Microsoft Visual C++ Redistributable，目标机缺 `VCRUNTIME140.dll` 等导致 exe 一启动即退出。
- 已改 `installer.iss` 根治：① `[Files]` 加 `Source: "installer\vcredist_x64.exe"; DestDir:"{tmp}"; Flags: deleteafterinstall; Check: not VCInstalled`；② `[Run]` 加 `vcredist_x64.exe /install /quiet /norestart`（Check: not VCInstalled）；③ 末加 `[Code]` 段 `VCInstalled()` 检测 `HKLM\SOFTWARE\Microsoft\VisualStudio\14.0\VC\Runtimes\x64` 的 `Installed=1`。
- 使用前需把官方 `vc_redist.x64.exe`（约25MB，learn.microsoft.com 最新 VC++ 可再发行）放到 `installer\vcredist_x64.exe`，否则 ISCC 编译会报文件不存在。
- 用户侧立刻解法：直接在**自己机器**装系统级「Microsoft Visual C++ Redistributable (x64)」，装完无需重装程序即可双击打开（VC++ 为系统全局依赖）。
- 实测：本工作区 Bash 出网被沙箱拦截（curl 下载 aka.ms/vc_redist.x64.exe 超时 `Connection timed out`），无法替用户把该 ~25MB 文件下到 installer 目录。需用户在**自己机器**下载 `vc_redist.x64.exe` 改名 `vcredist_x64.exe` 放入 `installer\` 后重跑 `build_installer.bat`。
- 用户重跑 bat 触发 `Source file installer\vcredist_x64.exe does not exist` 中止——即未放该文件。根因=缺文件，非脚本错误。
- 用户放好文件后重跑，[Code] 段报 `'BEGIN' expected`：根因=① [Code] 段注释误用 `;`（Pascal 里 `;` 是语句分隔符，非注释，须用 `//`）；② `Result := RegQueryDWordValue(...) and (Installed=1)` 中 `and` 优先级高于 `=`，会误解析成 `(RegQueryDWordValue(...) and Installed)=1`（Installed 为 Cardinal 类型不匹配）。已改为 `if RegQueryDWordValue(...) then Result := (Installed=1)` 写法修复。
